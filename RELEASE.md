# Выпуск новой версии лаунчера

Лаунчер — портативный exe: папка `NemesisLauncher/` (сам exe, `app/` с jar и
`runtime/` со вшитой Java). Ставить ничего не нужно, просто запускать —
либо скачать `NemesisSetup.exe` (установщик, см. ниже).

Автообновление устроено так:

* в репозитории [1kitikat1/Launch](https://github.com/1kitikat1/Launch) в ветке
  `main` лежит `version.json`;
* в его релизах лежит zip с приложением;
* при запуске лаунчер читает JSON, сравнивает версию со своей и, если вышла
  новая, показывает диалог «Обновить и перезапустить»: скачивание с прогрессом,
  подмена файлов и перезапуск — автоматически.

## 1. Поднять версию

`build.gradle` → `version = '1.0.0'` → `version = '1.1.0'`.

## 2. Собрать

```powershell
$env:JAVA_HOME = 'C:\Users\Kitikat\.jdks\corretto-21.0.12.1'
.\gradlew.bat packageRelease
```

На выходе:

| Файл | Что это |
|---|---|
| `build/jpackage/NemesisLauncher/NemesisLauncher.exe` | сам лаунчер (папка рядом — и есть приложение) |
| `build/release/NemesisLauncher-1.1.0.zip` | архив, который скачают те, у кого стоит старая версия |
| `build/release/version.json` | JSON, который кладётся в main репозитория Launch |

Если Gradle падает с «Failed to clean up stale outputs» — значит открыт
работающий лаунчер, закройте его и повторите.

## 3. Загрузить zip в Release

1. Открыть <https://github.com/1kitikat1/Launch/releases>.
2. *Draft a new release*: tag `v1.1.0`, название «Nemesis 1.1.0».
3. В *Assets* загрузить `build/release/NemesisLauncher-1.1.0.zip`
   (важно: имя zip и тег должны совпадать с тем, что записано в version.json —
   там уже всё подставлено).
4. В поле описания — что изменилось. *Publish release*.

## 3а. Установщик NemesisSetup.exe (если пересобирали)

Источник: `installer/` (C#, WinForms под .NET Framework 4.8 — встроен во все
Windows 10/11, поэтому exe весит ~0,4 МБ, ничего не тянет с собой).

```powershell
dotnet build installer\NemesisSetup.csproj -c Release
```

На выходе: `installer/bin/Release/net472/NemesisSetup.exe`.

Что он делает: спрашивает GitHub API **последний** релиз (`/releases/latest`),
берёт оттуда версию, описание и ссылку на `NemesisLauncher-*.zip`, качает архив
с прогрессом, распаковывает в `C:\NemesisLauncher`, создаёт ярлыки на рабочем
столе и в Пуске. Папка и версия в исходнике жёстко прошиты (`InstallDir`,
`ApiUrl`), сам exe в релиз загружать не обязательно — его меняют редко.

Важно: установщик ищет в релизе ассет по маске `NemesisLauncher-*.zip`,
поэтому сначала в релиз кладётся zip, потом (при необходимости) setup- exe.

## 4. Положить version.json в main

Скопировать `build/release/version.json` в корень репозитория Launch
(веб-редактор GitHub или `git`) и закоммитить в ветку `main`.
Файл читаемый, в нём:

```json
{
  "version": "1.1.0",
  "url": "https://github.com/1kitikat1/Launch/releases/download/v1.1.0/NemesisLauncher-1.1.0.zip",
  "notes": "Что изменилось в версии 1.1.0"
}
```

Поле `notes` попадает прямо в диалог обновления — пишите туда, что реально
изменилось.

После публикации JSON все, у кого стоит прошлая версия, при следующем запуске
увидят диалог обновления.

## Что происходит у пользователя

1. Запуск → фоновая проверка `version.json` (ошибки сети игнорируются,
   лаунчер работает в любом случае).
2. Версия новее → оверлей «Доступна версия X» с прогресс-баром.
3. «Обновить и перезапустить» → zip (~75 МБ) качается в `%TEMP%`,
   рядом отвязанным процессом запускается PowerShell-скрипт, окно закрывается.
4. Скрипт ждёт, пока процесс лаунчера полностью завершится, распаковывает архив
   поверх папки приложения (`robocopy /MIR`), снова запускает
   `NemesisLauncher.exe` и удаляет за собой zip, распаковку и сам себя.

Если лаунчер запущен не из exe (разработка из исходников), кнопка честно
пишет, что обновляться нечем.
